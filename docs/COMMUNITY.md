# Community & GitHub Discussions

This document sets the ground rules for GitHub Discussions and the broader
community spaces for SmartTableJS.

## Discussion categories

| Category            | Used for                                          | Not for                               |
| ------------------- | ------------------------------------------------- | ------------------------------------- |
| **Q&A**             | How-to questions, best practices, troubleshooting | Bug reports → open a Bug Report issue |
| **Ideas**           | Proposals, API sketches, feature seeds            | Confirmed bugs / promises             |
| **Show & tell**     | Your builds, wrappers, plugins, blog drafts       | Support Q&A                           |
| **Blog** (optional) | Long-form announcements & user stories            | —                                     |
| **Announcements**   | Maintainers only                                  | —                                     |

## Guidelines

- **Be kind.** Follow the [Code of Conduct](../CODE_OF_CONDUCT.md).
- **Search first.** Duplicate discussions are merged into the most complete
  one.
- **One topic per thread.** Split unrelated questions.
- **Use the templates.** Discussion templates prefill structure — keep it.
- **Give a complete repro for "doesn't work".** Include package versions,
  environment, and a minimal snippet or link.
- **Mark the best answer** for Q&A threads (click the checkmark) so future
  readers land on the solution.
- **Bugs belong in issues**, not discussions. When a maintainer confirms a
  Q&A thread is a bug, please open an issue (or a contributor will).
- **Features need an issue eventually.** Ideas that gain consensus get
  converted into Feature Request issues and tracked on the ROADMAP.
- **No promotions.** Keep it about the software; link-heavy self-promotion
  goes to _Show & tell_ and stays relevant to SmartTableJS.
- **No support for EOL versions.** Check `SUPPORTED_VERSIONS.md`.

## Escalation

- Security problems → GitHub Security Advisory (never a discussion).
- Rule enforcement → maintainers, per the Code of Conduct enforcement
  process.

## Maintaining this repo

- Tag helpful answers with 👍/💡.
- Convert ripe Ideas into feature issues (label `kind:feature`).
- Keep the templates in `.github/DISCUSSION_TEMPLATE/` in sync with the
  category slugs configured under Settings → Discussions.
